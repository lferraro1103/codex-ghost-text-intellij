# Local preview and safe acceptance

## Objective

Create one disposable non-document block preview below a valid comment and allow a fresh proposal to be inserted exactly once in a named Undo command.

## Tasks

1. Add a project `GhostPreviewService` plus pure `GhostBlockRenderer`; capture document/editor/selection/stamp, add one below-line block inlay, and cancel it on edit/caret/selection/replacement/disposal. Reject viewer, read-only, multicaret, unsafe inline block suffix and oversized/empty output.
2. Delegate valid Phase 1 action invocation to the service's explicit deterministic development fixture. Implement fresh acceptance with exactly one `WriteCommandAction` and one `Document.insertString`, preserving source comment and handling EOF/newline.
3. Add light-fixture tests for no mutation during display, source-comment preservation, EOF insertion, stale/edit cancellation, limits and repeated acceptance.

## Must Haves

- One preview only; preview never changes the document or its modification stamp.
- A second Tab after successful acceptance cannot insert the proposal again; stale editor/document/selection/stamp cannot insert.
- `Tab` acceptance is a single named undoable document insertion; comment stays untouched.
- Flagged assumptions: actual inlay paint ordering/color remains human visual UAT; native handler wrapper is delivered in plan 02.

## Threat Model

| ID | Threat | Severity | Mitigation |
|---|---|---|---|
| T-02-01 | Stale proposal tampers with changed source | high | Identity/stamp/selection gates before one write command; listeners cancel early. |
| T-02-02 | Preview mutates without consent | high | Inlay-only rendering, one Tab-only mutation path and tests. |
| T-02-03 | Inline block placement splits code | medium | Reject non-whitespace suffix after comment line. |
