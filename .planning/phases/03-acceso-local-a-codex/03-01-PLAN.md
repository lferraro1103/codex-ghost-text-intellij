# Safe local Codex diagnostic

## Objective

Give the user a native, actionable local Codex availability diagnostic using only App Server initialization, `account/read(refreshToken=false)` and `account/rateLimits/read`.

## Tasks

1. Locate a local native Codex executable without inspecting auth/config data. Start a bounded stdio child process with a sanitized credential environment; never use a shell or socket.
2. Implement bounded JSONL handshake and safe response categorization. No login/logout/config/model/thread/turn calls, no raw response/error logging, and always destroy the child.
3. Add an IntelliJ action and Spanish notifications for available, missing, login required, quota exhausted and generic connection/protocol failures; test locator/classifier paths.

## Must Haves

- The plugin uses existing local account state only and stores no credentials.
- A diagnostic never performs a model inference or starts a thread/turn.
- Timeout, malformed/oversized response, unknown server request and child failure are safe generic errors.

## Threat Model

| ID | Threat | Severity | Mitigation |
|---|---|---|---|
| T-03-01 | Credential disclosure | high | Remove credential env keys; never read/auth/config files or log raw data. |
| T-03-02 | Shell/command injection | high | Verified executable Path plus fixed ProcessBuilder arguments. |
| T-03-03 | Hung/malicious local process | medium | Bounded frames/deadline, destroy process and no EDT blocking. |
| T-03-04 | Accidental paid/API use | high | Require ChatGPT account type and reject API/unknown auth; no model API calls. |
