## Project

**Codex Ghost Text for IntelliJ**

Un plugin personal para IntelliJ que conecta con Codex local ya autenticado y transforma comentarios seleccionados en sugerencias de código. El usuario selecciona un comentario, invoca un atajo o una acción del menú contextual, y el plugin muestra un bloque de código transparente inmediatamente debajo del comentario.

**Core Value:** Convertir un comentario seleccionado en una propuesta de código insertable con `Tab`, sin salir del editor ni requerir una API key.

### Constraints

- **IDE**: IntelliJ Platform — el resultado debe ser un plugin nativo integrado al editor.
- **Authentication**: Codex local/App Server — sin API key ni OAuth implementado por el plugin.
- **Interaction**: Selección manual + menú contextual o shortcut — el usuario controla cuándo se consulta Codex.
- **Safety**: El archivo no se modifica hasta que el usuario acepte explícitamente con `Tab`.
- **Scope**: Uso personal inicialmente — se prioriza simplicidad y robustez local sobre distribución pública.

## Recommendation

### Core Framework

| Technology | Version | Purpose | Why |
|---|---:|---|---|
| Kotlin | 2.4.0 | Plugin implementation | Kotlin is the natural language for current IntelliJ Platform development; IntelliJ 2026.2 bundles Kotlin stdlib 2.4.0. Match it and do **not** package a second stdlib. |
| Java / JVM toolchain | 21 | Compile and run target | IntelliJ Platform 2026.1+ requires Java 21. |
| Gradle Kotlin DSL | Current wrapper compatible with the plugin plugin | Builds, tests, sandbox IDE, packaging | It is the officially recommended build route and keeps build logic type-safe with the implementation language. |
| IntelliJ Platform Gradle Plugin | 2.18.1 | IntelliJ dependency, `runIde`, packaging, verifier | JetBrains’ current documented top-level plugin is `org.jetbrains.intellij.platform` 2.18.1. Do not use obsolete Gradle IntelliJ Plugin 1.x. |
| IntelliJ IDEA Community target | 2026.2.0.1 initially | Development/sandbox platform | The current JetBrains dependency example uses this build. The personal plugin needs only the IDEA platform, not language-specific bundled plugins, because it acts on selected editor text. |

### Local Codex Integration

| Technology | Version | Purpose | Why |
|---|---:|---|---|
| `codex app-server --stdio` | User-installed Codex version | Local, authenticated Codex harness | It uses the existing Codex login without putting credentials in the plugin. `stdio` JSONL is the documented default transport; the WebSocket listener is marked experimental/unsupported. |
| JSON-RPC 2.0 client | In-plugin implementation | Request/notification correlation | App Server is bidirectional: after `initialize` and `initialized`, the plugin starts a short-lived thread/turn and consumes streamed notifications. A tiny client over process stdin/stdout is lower-risk than adding another server. |
| `kotlinx-serialization-json` | 1.9.0 | Parse/compose JSON-RPC envelopes | Use only `JsonObject`/`JsonElement` for this evolving protocol; ship this small library with the plugin instead of depending on an undocumented IDE-bundled JSON parser. Keep DTOs narrow and tolerate unknown fields. |
| Runtime schema generated by Codex | Same as installed Codex | Development/compatibility validation | `codex app-server generate-json-schema` or `generate-ts` produces schemas matching that exact Codex version. Use it as a test fixture, not as a hard-coded protocol copy. |

### IntelliJ Integration

| Technology | Version | Purpose | Why |
|---|---:|---|---|
| `DumbAwareAction` + Action System | Platform API | Context-menu command and configurable trigger shortcut | It is the supported way to add an item to `EditorPopupMenu`, use the selected text, and offer a user keymap shortcut. The action’s `update()` remains cheap; generation runs only from `actionPerformed()`. |
| Project-level light service | Platform API | Own process session, request cancellation, preview state | A service is lifecycle-aware and can terminate its subprocess/coroutines when the project closes. Avoid deprecated plugin components. |
| IntelliJ coroutine scope | Platform-provided | Non-blocking process I/O and cancellation | Use a service-injected `CoroutineScope`; do not block the EDT while Codex responds. Avoid declaring a competing `kotlinx-coroutines` runtime unless a compile check proves it is needed. |
| Editor block inlay / custom renderer | Platform editor API | Multiline, non-document ghost preview below the selected comment | The desired output is a code block **below** a selection, not conventional same-line completion. A disposable block inlay can preview it without modifying the document, and can be removed on Esc, edit, caret move, or new request. |
| Explicit write action + `Document.insertString` | Platform API | Commit proposal on `Tab` | Only the accept path mutates the document, inside a write command/action. IntelliJ requires document changes to respect the write-action model. |
| `InlineCompletionProvider` | Platform extension point | Future native inline-completion experiment | This extension point exists, but related insertion/partial-accept hooks are internal or experimental. Do not make MVP behavior depend on those hooks; evaluate it later for a more Copilot-like rendering path. |

### Validation and Tests

| Technology | Version | Purpose | When to Use |
|---|---:|---|---|
| IntelliJ Platform test framework | Platform-provided | Unit/integration tests in a sandbox IntelliJ project | Test action enablement, preview lifecycle, and document insertion. |
| `TestFrameworkType.Platform` | Gradle plugin API | Test framework dependency | Include from the start rather than wiring test jars manually. |
| Fake `CodexTransport` | Test-local interface | Deterministic protocol tests | Production owns `AppServerTransport`; tests substitute scripted JSONL responses and overload/errors. |
| IntelliJ Plugin Verifier | Gradle-plugin task | Compatibility checking | Run before every usable build against the exact IDE line(s) the user has installed. |

## Alternatives Considered

| Category | Recommended | Alternative | Why Not |
|---|---|---|---|
| Codex connection | App Server over child-process stdio | WebSocket listener | OpenAI’s App Server README marks WebSocket experimental/unsupported. It also exposes a local port unnecessarily for a personal plugin. |
| Codex connection | App Server | OpenAI API key / API backend | Violates the core requirement to use the existing Codex account with no API key. |
| Preview | Block inlay owned by the plugin | Directly write generated code then undo on reject | Breaks the guarantee that the file remains unchanged until explicit acceptance and corrupts undo/history expectations. |
| Preview | Block inlay MVP | `InlineCompletionProvider` as the only implementation | Native inline completion is promising, but the manually triggered, multiline-below-selection interaction and acceptance plumbing need target-version proof; auxiliary hooks are internal/experimental. |
| Serialization | Package `kotlinx-serialization-json` 1.9.0 | Rely on a bundled Jackson/Gson version | Bundled libraries vary by IDE release and classloading can be fragile. A small explicit JSON dependency makes the protocol client reproducible. |
| State/lifecycle | Project service | Deprecated `project-components` | JetBrains recommends services; components impede dynamic plugin loading. |
| Distribution | Local ZIP installed from `buildPlugin` | Marketplace publishing | This is a personal plugin. Signing, Marketplace compatibility ranges, and public support add no MVP value. |

## Implementation Boundaries

## Versioning / Compatibility Policy

- Pin the development target in `gradle.properties`; do not use floating `+` versions.
- At plugin startup, run a cheap availability check for the `codex` executable. On request, expose a clear unavailable/unauthenticated state rather than attempting login or reading account files.
- Since App Server schemas are version-specific and the protocol is evolving, include a protocol-capability/compatibility check after `initialize`. Fail closed with “Update Codex or plugin” if required methods/events are absent.
- Do not specify `untilBuild` for a personal build. Run `verifyPlugin` when moving to a new IntelliJ release; create a version-specific branch/build only if the verifier finds an incompatibility.
